# My Cases — Independent CourtTrack Website

A self-hosted, password-protected cloud version of the PC v10 / Mobile v10 tracker for the Karnataka High Court. This is **not** an official court product. It reads publicly available High Court data and the court's interactive List No. passed-over popup. Real-time accuracy depends on the court website.

## What stays the same

- Mobile (`/mobile`) and desktop (`/`) use the same private database.
- Five-column board (CH No., List No., SL No., Case No., Stage).
- Tap CH to open the official cause list, tap SL for the next five matters, tap List No. for the passed-over popup.
- Auto-check passed-over cases every ~2 minutes while the service is running during the configured daily 08:00–20:00 IST monitoring window. A court-board check runs about every 35 seconds in the same window.
- Origin list matching for passed-over cases; they can be listed under a different currently displayed list.
- Lunch pause 13:30–14:30 IST, random calls, conservative ETA, finished/pending counts.

## Deploy on Render (recommended setup)

This Blueprint requests a **paid web service (1 CPU / 2 GB RAM) and a persistent disk (5 GB)**, rather than the free service that sleeps and loses its local data. Review Render's billing before deployment. Chromium is required to read the High Court's interactive popup; 512 MB is typically insufficient for multiple browser checks.

1. Extract the ZIP on your PC. Create a **new private GitHub repository** and upload the *contents* of the `CourtTrack_Cloud_Website` directory (not the parent directory). `render.yaml`, `Dockerfile`, `app.py`, `engine.py`, `scraper.py`, `cloud_auth.py` and `static/` must appear at the **repository root**. Do not upload any existing `data/` folder or `.env` file.
2. In [Render Dashboard](https://dashboard.render.com), select **New > Blueprint**, connect the repository, and specify `render.yaml` as the Blueprint path.
3. When prompted for `COURTTRACK_PASSWORD`, enter a **unique, strong password at least 12 characters**. Do NOT commit the password in GitHub. The signing secret is generated automatically.
4. Review the compute-plan and disk costs, then deploy. Wait for the service to be **Live**. The Docker build installs headless Chromium and its Linux dependencies and can take longer than a basic website deployment.
5. Open the HTTPS URL supplied by Render (example structure: `https://karnataka-courttrack-cloud.onrender.com`, but use the actual URL given by your account). Sign in with your password. Use `/mobile` on Android or iPhone and `/` on PC. Add a shortcut using **Add to Home Screen**.
6. For a first live test while the court is sitting, enter bench, CH, list, SL and case number. Compare the displayed board and passed-over modal with the official court website; a cloud IP may be blocked, delayed or receive a different response. The app intentionally shows **Not Verified** when source checks fail.

## Data persistence / security

- The `TRACKER_DATA_DIR` environment variable points to `/app/data`, the Render persistent disk mount. User-entered case records survive reboots and redeploys. The server must remain one instance and one Uvicorn worker because SQLite and the polling state live in this process.
- All case APIs, snapshots and export require a valid password session in cloud mode. The login cookie is signed, `HttpOnly`, `Secure`, and `SameSite=Lax` and expires after 12 hours. HTTPS is supplied by Render.
- For security, store your GitHub repo as **private**, use Render's environment-variable settings for credentials, and only share the website link with people you trust.
- The current PC and cloud tracker are **separate databases**. Existing local entries do not appear automatically on the new host. Enter your cases on the hosted site (case history from the old PC is not transferred automatically).
- Download your own backup at `/api/export` while signed in. The hosting disk is not a substitute for keeping your own backups.
- Avoid unnecessary requests to the judicial website. Official court data may be stale or fail to load; this is not legal hearing confirmation.

## If deployment fails

- `Blueprint file render.yaml not found`: upload `render.yaml` to the **top level** of the GitHub repository on the **main** branch.
- `libatomic.so.1`: the provided Dockerfile explicitly installs `libatomic1`; check that Render is using this Dockerfile and clear build cache.
- Startup rejects the configuration: ensure `COURTTRACK_PASSWORD` is 12+ characters and `COURTTRACK_SESSION_SECRET` exists (generated by the Blueprint).
- `Not Verified`: check `Logs` in Render and compare with the official High Court display board. The cloud provider's IP may be restricted by the judiciary website.
- Wrong court position: verify the official update timestamp; an unverified or out-of-order call is not counted as concluded.

## Optional local cloud-mode test

Run `CLOUD_MODE=1 COURTTRACK_PASSWORD='your-long-test-password' COURTTRACK_SESSION_SECRET='at-least-32-random-characters-xxxxxxxx' DISABLE_POLLER=1 uvicorn app:app --host 127.0.0.1 --port 8901` (Bash syntax). The secure session cookie requires HTTPS, so for full login testing use an HTTPS reverse proxy or the deployed Render URL.

## Limits

- Always-on monitoring requires a running paid web service. Deployments and host downtime interrupt polling.
- No push notifications after closing the browser. This is a live dashboard, not a background phone notification service.
- Not a substitute for the official display board/court staff. No guaranteed hearing ETA.
